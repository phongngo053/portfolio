The short version

I'm a Backend Developer and Software Engineer at FPT Software, currently working with Java. My day-to-day stack is Node.js with NestJS, Express, TypeScript and JavaScript — the part of the stack where the data, the contracts and the failure modes live.

I grew up in Hue and graduated from Hue University of Science. Outside of work I read novels, mostly at night, which is the same part of the brain I use to design an API.

The projects on this site are mine, not coursework I was handed. A browser extension that reads quizzes off the screen, a subtitle tool that translates YouTube in real time, a food-ordering platform rebuilt twice — once as a monolith, once as microservices. Most of them started because I needed the thing, and I decided building it was faster than searching for it.

I like clean boundaries, boring technology and small diffs. I don't like clever code that needs a paragraph to explain. Everything on this site is plain HTML, CSS and JavaScript — no framework, no build step, nothing between you and the browser.

How I work

Three habits that survived every project so far.

Start with the contract

Before writing a service I decide what it exposes and what it refuses to expose. An API that says no early is cheaper than a data model that has to be migrated later.

Make it runnable

Every project of mine clones and starts. A local setup that takes one command beats a perfect README that assumes a machine I no longer own.

Leave it readable

Naming, small functions, no clever abstractions. I optimise for the next reader — often me, six months later, wondering what I was thinking.
